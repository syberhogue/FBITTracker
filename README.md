# Ontario Tech FBIT Tracker

Production-oriented React and Supabase implementation of the FBIT academic operations tracker. The original `prototype.tsx` remains in the repository as the visual reference.

## Run the UI

```bash
npm install
copy .env.example .env.local
npm run dev
```

`VITE_DEMO_MODE=true` uses fictional in-memory records. Set it to `false` and use the URL and publishable key printed by the Supabase CLI to exercise the full backend.

The public home page at `/` lets assigned faculty submit final grades without signing in. The authenticated operations dashboard is at `/dashboard`; staff authentication begins at `/login`.

Authenticated users can create personal tracker templates under `/settings`. Deans can also publish faculty templates for every active user and upload or edit an academic year's important dates. Template stages store day offsets from an anchor date, so applying a template creates the same workflow with a newly calculated schedule.

## MSc student tracker

Open **MSc student tracker** in the sidebar (`/graduates`) to add students, record supervisors, set a defence date, and track report and examination completion dates with notes. The register supports search, active/completed filters, and a needs-attention view.

Each student's overall timeline shows colored task symbols and a **Today** marker. Hover or keyboard-focus a symbol for `category: item` details; select it to update the item. Short labels beside the timeline lanes jump to their sections, and each section has **Back to top**. Green duration bars connect program start to the two-year target; red bars connect that target to the three-year maximum. Dark horizontal baselines and dotted vertical connectors identify each item's lane. Each category has its own timeline that remains visible when folded. Unscheduled items are folded by default. Shaded calendar-semester blocks distinguish Fall, Winter and Summer (compact labels such as F26, W27 and S27). Lists use alternating shading, and semester report labels use only the semester and year. **Defense Date** and **Thesis Submission Date** are highlighted in the student summary.

Selecting supervisor and optional co-supervisor accounts fills their names automatically. The **Suggested Defence Date** defaults to one calendar month before the two-year anniversary (a Fall 2024 start suggests August 1, 2026). Changing the start semester/year recalculates this default. In the student summary, click **Defense Date** or **Thesis Submission Date** to edit that date directly. Submission defaults to five weeks before defence; a custom date persists when defence changes and updates the suggested chapter windows. Use the automatic-date checkbox to restore the calculated submission date. **Completed All MSc Requirements** is in the student summary, with its own date picker and **Save date** action; **Edit MSc completion** lets you change or clear completion later. Thesis revision selection remains in the final thesis-package task.

The summary's **Supervisory Committee** panel lists supervisors, additional members, the chair and University Examiner. **Edit members** supports supervisor account selection, additional member names, a chair selected from committee members, and a University Examiner name. An additional member is required beyond the supervisor/co-supervisor, and a University Examiner is needed for defense. Incomplete committees can be saved while planning; missing appointments are highlighted. Additional member and examiner names do not grant application access.

Scroll the mouse wheel over any timeline graph to zoom around the pointer. Zoom buttons provide keyboard/touch alternatives; arrow buttons move through the visible dates and **Reset zoom** restores the full timeline. **Fit to stages** frames Today through the last scheduled stage on that timeline, with padding at both ends; timelines with no future stages show a short window around Today. The closest view covers seven days. As you zoom, the axis adds month, week (Monday) and day divisions; labels thin automatically to stay readable. Left-click and drag empty graph space to pan while zoomed. Section labels are integrated with the graph's rows and connect directly to their horizontal baselines.

Drag a course marker or duration bar to another semester; its start and deadline move to that semester's boundaries. Drag chapters or custom deadlines to refine their dates: wider views snap to weeks, while views of 120 days or less snap to individual days. Chapter drags move both ends of the writing window, preserving its length. The oral-exam marker updates the defense date, and either thesis-submission marker updates the submission date and dependent suggested chapter windows. Fixed report, committee and program-limit deadlines remain calculated. A preview shows the date before release, Escape cancels, and failed/invalid moves leave the saved schedule unchanged. Completion records and notes are retained.

Use **Export** beside **+ Category** for a complete TXT or CSV snapshot, a printable PDF report, or an ICS calendar. PDF opens a formatted report: choose **Save as PDF** in the browser's print destination. TXT, CSV and PDF include unscheduled items, committee details, notes and linked trackers. The calendar includes only scheduled items, with all-day deadlines and full course/chapter durations, stable event identifiers and UTF-8 text. Import the `.ics` file using [Google Calendar's import instructions](https://support.google.com/calendar/answer/37118?hl=en). Exports are snapshots, not live calendar subscriptions.

The default **Thesis/Defence planning** category includes the student/supervisor examination tasks and five one-calendar-month writing windows: Literature Review due at the end of semester one; Introduction draft due at the start of year two; Methodology and Results in successive windows before submission; Discussion/Conclusions in the final month before submission. Submission is five weeks before the suggested defence. A planning checkpoint suggests agreeing the defence date and examining committee eight weeks beforehand. Chapter start dates default to one month before the expected date and can be edited independently. Choosing a custom start saves both ends of the writing window, preserving it through defence rescheduling. **Use one-month writing window** resets the start; **Use suggested date** restores automatic scheduling for both dates. Chapters support Not started, Draft and Completed states; half-shaded timeline symbols denote drafts, and only Completed counts toward completion.

The default **Supervisory Committee** category requires formation within eight calendar months of the program start and a meeting each semester, suggested at semester end. Meeting and report schedules stop after the recorded program-completion semester. Actual meetings can be recorded earlier than their deadlines.

Use **+ Category** beside **Edit student & schedule** to add an area, **+ Deadline** in an area's header to add a dated item, and the color picker followed by **Save color** to change the area's color. Custom deadlines can be rescheduled with **Edit deadline**. Built-in semester and defence deadlines remain calculated from the program schedule.

Choose **Item type / symbol** when updating a built-in task or adding/editing a custom deadline. Form, Report, Thesis, Meeting, Course and Milestone each have a distinct symbol; defaults follow each task's purpose.

The Coursework area tracks five individual **Course requirements**. Double-click a shaded semester (or focus it and press Enter/Space) to assign an available requirement. Only unassigned requirements appear in the picker. Each course spans the entire Fall, Winter or Summer semester and is due on its final day; several requirements can share a semester. Use **Update** or select the course marker to change its semester or record completion. The course total counts individually completed requirements. Existing task keys and history remain unchanged; older dates remain until explicitly assigned to a semester. Completion date inputs initially show the expected date (or an existing actual completion date); **Mark completed** must be selected to record completion. Saving notes or future plans alone does not complete a task.

Use **Linked trackers** to connect existing thesis, paper, or other process trackers. Each linked tracker includes an **MSc progress** link back to the selected student. Links do not grant access to either record; users must already be authorized for both. Removing a link leaves the tracker intact.

- Fall starts September 1, Winter January 1, and Summer May 1. Completion targets are exactly two years from that start date; maximum deadlines are exactly three years.
- Required research progress reports are due December 31, April 30, and August 31. Nine semesters are initially scheduled. Reports continue each semester for active students past the maximum; a program completion date stops new reports after the completion semester. Recording completion tracks receipt; it does not submit a report to the university.
- Thesis/Defence planning includes the student/supervisor tasks from the supplied examination timeline: Form 2.2M to the program office at −6 weeks, thesis submission at −5 weeks, oral exam, and final thesis package within +4 weeks for minor revisions or +6 calendar months for major revisions. Program Office/GPA and SGPS administrative sections are excluded from planning. Existing administrative history remains stored; student/supervisor task keys and completions are preserved and custom student deadlines move into Thesis/Defence planning.
- Defence tasks use the editable suggested defence date. Rescheduling preserves recorded completions and notes. Revision deadlines never extend the program maximum; conflicting dates are flagged.
- Deans and academic directors manage all students. Chairs/program leads use their existing organizational scopes. Graduate supervisors/research leads can create students within their scope and manage their own records; linked supervisor and co-supervisor accounts also grant progress access. Student details and report records are not available anonymously. No new student login or GPA/SGPS role is introduced; those labels describe task responsibility.

Existing manually chosen defence dates and task records are preserved. Apply pending migrations to your Supabase environment before using the module outside demo mode. Demo students remain in memory and reset on a browser reload, like demo process trackers.

`20260922151416_graduate_courses_committee_dates.sql` adds semester course assignments, committee appointments and submission-date overrides, with database checks for semester boundaries, submission-before-defence and chair membership.

Right-click a timeline marker, duration bar, or unscheduled item and choose **Delete deadline**. Each expanded deadline row also has a delete button; each category header has **Delete category**. Deletions are stored so generated defaults stay removed, and deleted items are excluded from timelines and exports. Editing any task lets you change its **Item type / symbol**, including **Research Paper**. Drag status and hover details appear underneath the graph so they do not move it while dragging. PDF exports include a vector overall timeline with semester bands, program target/maximum periods, duration bars and a dated Today marker.

The default **Funding** category has **+ Funding** for GRA and RA appointments. Specify the grant/funding source, total CAD amount, start semester/year and one to three semesters (one year maximum). Funding spans complete semesters; a separate form deadline is scheduled one calendar month before the start. Edit or drag the funding period to update its dates and form deadline together. Record form submission through its task marker or **Update**. Amounts describe the total funding period, not a per-semester payment.

**Templates & settings → MSc resources** stores shared HTTP/HTTPS links with a description and student/supervisor audience. These appear in **Resources** at the bottom of every student. Active staff can view links; roles that create MSc records can contribute resources, and the author or a dean/academic director can edit or remove them. `20260922155953_graduate_funding_resources_deletion.sql` adds Funding defaults, period validation, deletion markers, Research Paper symbols and the protected resource library. Apply this migration to hosted Supabase before using these additions outside demo mode.

## Curriculum Change Tracker

Open **Curriculum Change Tracker** in the sidebar (`/curriculum`). Create a proposal using **Major Program Modifications**, **Minor Program Adjustments**, **Minor Curriculum Changes**, **New Programs**, **New Specializations**, **New Courses**, or **New Pathway**. New courses follow minor curricular governance; specializations and pathways follow major governance. Each proposal has an overall timeline and collapsible committee sections with their own timelines, stage outcomes, actual completion dates, notes and editable HTTP/HTTPS proposal/resource links. Add extra stages for consultation or other deadlines. The timeline uses the MSc tracker’s zoom, pan, Today marker, semester shading and section navigation.

**Standard** minor curricular changes use UEC approval → FC approval → USC information reporting; standard major modifications and minor program adjustments use UEC → FC → USC → AC approval, as requested. **V1** explicitly applies those four approval stages to any type. **V2** adds UEC and FC information stages before the four approvals. Minor program adjustment guidance links explain the policy’s AC information-reporting distinction. Template and process identity are fixed after creation to preserve history; individual stages remain editable.

**Committee calendar** lets deans, academic directors, chairs and program leads edit the shared academic-year schedule, add/delete meetings, change agenda lead times and mark voting availability. Supplied USC/AC dates are seeded for **2026–27**; future university dates require entry. FC defaults to the first Tuesday with a seven-day agenda lead; UEC to the second Tuesday with a configurable five-day lead (within the supplied 3–5 day guidance). ARC is quarterly, with exact dates entered by staff. A zero lead time means no advance agenda deadline has been specified. Initial schedules respect stage order and agenda lead times; approval stages skip information-only meetings. Calendar edits affect new schedules. **Reschedule pending stages** applies the revised calendar while retaining completed-stage schedules, outcomes, dates, notes and links. Missing meetings and their dependent stages remain unscheduled. Manual dates outside the calendar are flagged for review.

Drag a pending stage on the overall or committee timeline to reschedule it. Committee stages snap to the first configured meeting on or after the dragged date that satisfies preceding stages and agenda lead times; approval stages require a voting meeting. Dependent committee stages and their agenda deadlines move together, while manual deadlines retain their spacing. The drag previews affected dates before saving the full proposal together. Completed stages stay fixed. Escape cancels; missing meetings, conflicts with completed history or the NOI expiry block the move and leave the saved schedule unchanged.

New programs begin with NOI Development → ARC approval → NOI publication. Record actual ARC approval before recording publication; actual publication starts the two-calendar-year governance window. Governance schedules remain unscheduled until publication is recorded (individual dates can still be planned manually). The module flags NOI expiry, overdue stage/agenda deadlines, reversed stage order and the **January 31** USC/GSC receipt cutoff in the year the implementation academic calendar starts (for example, January 31, 2027 for Fall 2027).

Under **Templates & settings → Committee meetings**, select an academic year and committee, then choose **Meeting frequency** to auto-fill its draft list. Weekly, every two weeks, monthly, quarterly and yearly schedules are supported. Monthly/quarterly dates can use a week and weekday (including the last weekday), or a fixed day of the month; shorter months use their last day. Choose the schedule’s start/end dates, then override individual meeting dates, agenda leads or voting availability and delete unwanted meetings. **Save committee calendar** saves the reviewed list for all committees in that academic year. Changing recurrence replaces only the selected committee’s draft list. Saved overrides and deletions remain intact when reopened; the frequency starts at **Custom / saved dates**. Unsaved drafts are retained while switching committees or years within the form. The tracker’s **Committee calendar** dialog uses the same controls.

The migration `20261001175019_curriculum_change_tracker.sql` adds the protected proposal/calendar tables, validates workflow snapshots and safe links, rejects approvals on saved information-only sessions and enforces new-program prerequisites. Versioned saves detect concurrent edits. Active staff with tracker-creation roles can create within their existing organizational scope; creators, deans/academic directors and scoped chairs/program leads can manage proposals. Calendars are readable by active staff and editable by the governance roles above. Anonymous access is revoked. Apply this migration to hosted Supabase before using the module outside demo mode. Demo proposals and calendar changes are in memory and reset on a browser reload.

## Run Supabase locally

Docker Desktop must be running.

```bash
npm run supabase:start
npm run db:reset
npm run db:test
```

Local Studio is available at `http://127.0.0.1:55323`. This project uses the 5532x port range to avoid colliding with other local Supabase projects. Never expose the local stack to external traffic.

## Security and privacy

- The browser validates grade CSV and Excel files and sends only numeric grades; student names, IDs, raw files, and original filenames are never transmitted or persisted.
- Public submissions use the narrowly scoped `submit_public_grade_upload` RPC. Direct anonymous table access is revoked. Existing courses require an active instructor assignment; genuinely new course codes require an exact active faculty name/email match before the course and assignment are created. Each course/email is limited to five replacement submissions per hour.
- Every exposed table has RLS. Role checks use server-controlled profile records and organizational scopes.
- The `manage-user` Edge Function is the only app path using the Supabase secret key and re-checks that the caller is an active Dean.
- Stage documents are private and restricted to PDF, DOC, and DOCX files up to 10 MB.
- Each tracker stage can also hold multiple named HTTP/HTTPS links. Links open directly from the detailed checklist and can be removed individually by users who can manage the tracker.

Grade uploads accept `.csv` files and the first worksheet of `.xlsx` files. The instructor workbook uses these headers: `Semester ID`, `Course Code`, `Last Name`, `First Name`, `Student ID`, `Final Grade (%)`, `Final Letter Grade`. CSV exports that use `Section` instead of `First Name` are also accepted. The file's semester selects the destination term and accepts labels such as `W26`, `W2026`, `Winter 2026`, `F26`, `F2026`, and `Fall 2026` (plus equivalent Spring/Summer labels and official numeric semester IDs). Grade Analytics provides a CSV template pre-filled with the selected term, lets deans and academic directors create terms, and lets authorized course submitters delete a selected course's upload history and derived analytics for the selected term without removing its course assignment.

Course codes are inferred as four letters, four numbers, and an optional `U` or `G`. Spacing is ignored and an omitted suffix defaults to undergraduate, so `BUSI1100`, `BUSI 1100`, `BUSI1100U`, and `BUSI 1100U` resolve to the same course. If the canonical code is absent, an authorized upload adds the course and current-term assignment. Identical grade data for that course and term is treated as a duplicate and does not create another upload version.

Important-date imports accept the first worksheet of an `.xlsx` file. `Fall semester`, `Winter semester`, and `Spring/Summer semester` rows switch the active semester. Each description becomes a separately managed event; a blank date cell inherits the last explicit date or date range, and the importer generates an editable representative short name.

Because the public flow intentionally has no authentication, matching a name and email to a course assignment does not cryptographically prove the submitter's identity. Before an Internet-facing launch, pair the existing controls with an institution-approved verification step such as an emailed one-time link and bot protection.

Before production use, configure hosted Supabase Auth URLs/SMTP, review institutional data-retention requirements, run database advisors, run all tests, and perform role-specific smoke tests.
